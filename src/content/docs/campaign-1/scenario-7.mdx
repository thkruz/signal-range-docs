## Uplink Validation Sequence

Post-maintenance validation follows this sequence. Each phase builds on the previous.

### Phase 1: System Health Check

Before touching RF equipment:

- [ ] Check Dashboard for active alarms
- [ ] Verify GPSDO locked
- [ ] Note any fault conditions

### Phase 2: Receive Chain Verification

Confirm the receive path is operational:

- [ ] Antenna tracking TIDEMARK-1
- [ ] LNB powered, reference locked, thermally stable
- [ ] Beacon visible at 1,074.5 MHz IF (Span 2 kHz, Min Amp -100 dBm, Max Amp -30 dBm; it reads about -49 dBm)
- [ ] Signal level nominal

### Phase 3: Transmit Chain Configuration

Configure the TX modem for TIDEMARK-1 uplink:

- [ ] TX IF frequency: 1,057 MHz
- [ ] Bandwidth: 36 MHz
- [ ] Modulation: QPSK
- [ ] FEC: 3/4
- [ ] Power: -7 dBm
- [ ] Enable TX modem output

### Phase 4: Loopback Validation

Test the low-power TX chain before engaging the HPA:

- [ ] Reduce BUC gain to 20 dB for loopback (keeps the LNB linear, see below)
- [ ] Enable BUC loopback mode
- [ ] Unmute BUC
- [ ] Verify the loop carrier on the spectrum analyzer at 1,532 MHz IF (normal LNB LO, see below)
- [ ] Confirm TX modem output is clean

<Aside type="note">
Loopback testing feeds a coupled sample of the BUC output back into the receive chain without transmitting through the antenna. Nothing in the transmit path is switched out: the BUC still drives the HPA input, so the HPA stays disabled until the loop test is done. This validates the TX modem and BUC are working before you commit RF power to the air.
</Aside>

### Phase 5: Uplink Enable

After successful loopback validation:

- [ ] Verify encryption status (AES-256 required)
- [ ] Disable BUC loopback mode
- [ ] Set BUC gain back to 23 dB (at 20 dB the HPA is 3 dB short of drive)
- [ ] Enable HPA output
- [ ] Adjust HPA backoff for required output power: above 400 W (TIDEMARK-1 link budget minimum). The HPA makes 60 dBm (1 kW) at P1dB, so 3 dB of back-off gives 57 dBm (501 W) and 4 dB gives 56 dBm (398 W, just short). Below 3 dB the overdrive alarm trips.
- [ ] Verify uplink operational

The Ops Log records each power setting as you change it, for example "BUC gain set to 23 dB (was 20 dB)" and "HPA back-off set to 3 dB (was 10 dB)", so the shift log can be read back from it.

## Loopback Test Reference

### Why Loopback First?

Loopback testing catches configuration errors before they cause interference. A misconfigured TX frequency or incorrect modulation settings are much easier to diagnose in loopback than by analyzing satellite return signals.

### Where the Loop Carrier Appears

A C-band LNB only receives about 3.4-4.2 GHz, so it never sees the 6 GHz uplink directly and you do not retune it. The station's test loop runs the coupled BUC sample through a loop translator that shifts it down by the satellite's own translation frequency (2,225 MHz), so the loop carrier arrives where our downlink will be:

| Stage | Frequency |
|-------|-----------|
| TX modem IF | 1,057 MHz |
| BUC output (7,000 - 1,057) | 5,943 MHz |
| Loop translator (5,943 - 2,225) | 3,718 MHz |
| LNB IF, normal LO 5,250 (5,250 - 3,718) | 1,532 MHz |

Leave the LNB LO at 5,250 MHz and look at 1,532 MHz IF (Span 50 MHz, Min / Max Amp -100 / -20 dBm, RBW Auto). The 36 MHz carrier sits in the same slot the RX modem watches for our downlink, so the loop also shows you what the receive side will see once the uplink is live. On RX Analysis a carrier this clean reads Effective C/N well under Raw C/N with ADC Status OPTIMAL: the grey ceiling line (about 40 dB) is the converter's own limit, and Raw C/N combined with it gives the Effective figure. It is not a fault.

### BUC Gain for Loopback

| Mode | Recommended Gain | Reason |
|------|-----------------|--------|
| Normal TX | 23 dB | About 16 dBm drive to the HPA from the -7 dBm modem, well under the BUC's 28 dBm P1dB |
| Loopback Test | 20 dB | Keeps the LNB linear (below) |

The test loop (a directional coupler, a pad and the loop translator) feeds the BUC output into the LNB about 66 dB down. At 60 dB gain the LNB compresses at about -50 dBm in (its output P1dB is +10 dBm). At 23 dB the loop puts -50 dBm into it: 0.7 dB of compression and an "LNB input overload" alarm, so the carrier you measure is distorted by the test itself. At 20 dB it gets -53 dBm, 3 dB under, about 0.2 dB of compression: a clean, linear look at the modem and BUC. Put the gain back to 23 dB before the HPA goes on.

## Escalation Guidelines

**Handle Yourself:**
- BUC configuration issues (mute state, loopback mode, gain)
- TX modem frequency and parameter configuration
- Loopback test execution
- HPA enable sequence
- Reference lock faults (power cycle usually resolves)

**Inform Dana:**
- Equipment faults that don't clear after troubleshooting
- Unexpected alarm conditions
- Validation complete (so she can update the shift log)

This is standard post-maintenance validation. Work methodically through each phase.
