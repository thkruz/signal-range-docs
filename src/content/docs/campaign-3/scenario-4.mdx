## What AFC Actually Does

**Automatic Frequency Control** is a loop, and it is not clever. Every update
it reads exactly one number — the carrier's offset from the center of your
channel, the same **OFFSET** readout you were using by hand — and slews the
VFO to re-center whatever it is currently locked to.

| Property | Value |
|----------|-------|
| Input | Measured carrier offset (Hz) |
| Slew rate limit | 200 Hz per update |
| Deadband | ±10 Hz (inside this it holds still) |
| Requirement | **There must be a carrier to measure** |

<Aside type="caution">
That last row is the whole limitation. AFC re-centers a signal it already has.
It cannot find one, cannot predict one, and cannot recover from a deep fade —
if the carrier leaves the passband, the loop has nothing to measure and simply
stops. A human operator knows where the signal *will be* in ten seconds. The
loop only knows where it *was*.
</Aside>

It will also happily follow the wrong signal. If a stronger carrier wanders
into your channel, AFC re-centers on that instead, with no opinion about
whether it's the thing you wanted.
