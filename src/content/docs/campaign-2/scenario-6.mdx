## Audit Trail Reference

| Column | Meaning |
|--------|---------|
| Time | UTC timestamp of the action |
| Actor | Account that performed it |
| Category | auth, config, or command |
| Severity | info or warning |
| Flag | Marks the entry for the monthly return |
| Sign Off Review | Records that the whole trail was read, end to end |

### What routine looks like at GW-01

| Pattern | Expected |
|---------|----------|
| Console logins by site staff | During shift hours, 0600 onward |
| Receiver and antenna configuration changes | Made by op-charlie or the operator on duty, logged as config |
| TT&C command acknowledgements | Logged as command, during pass windows |
| COMSEC key rotation | Logged as command, by the operator who ran it |
| Monitoring service telemetry polls | Regular, on the half hour |
| Remote logins from SH-02 | Fiona, during her shift |

<Aside type="caution">
Severity is a hint, not a verdict. An entry earns a flag on what it is, when it happened, and who did it, not on whether it succeeded. Six failed attempts that never got in are still six attempts, at an hour when nobody should have been trying.
</Aside>

## Escalation

**Handle yourself:**
- Flagging entries for the return
- Disabling accounts whose authorisation has lapsed
- Signing off the trail

**Ring Charlie, then London:**
- Any successful authentication by an account that should not have one
- Configuration or command entries by an actor you cannot account for
- Evidence that key material was touched outside a scheduled rotation

None of the above is expected today. That is why you read the whole log rather than the interesting-looking bits.

## End of Briefing

"Nothing happened" is a conclusion, not an assumption. You reach it by reading everything, and a return that says so is only worth anything if you did.

A dormant account with maintenance privileges is exposure whether or not anyone used it. If somebody was trying it at three in the morning, London will want to know that too.

Good luck.
