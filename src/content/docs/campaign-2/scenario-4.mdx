## Two Keys

| Key | Where | What it does | State at turnover | Today |
|-----|-------|--------------|-------------------|-------|
| **Command-link authentication key** | TT&C console, COMSEC panel | Signs every command so the spacecraft can prove who sent it. `requireValidKey` is on: Pending Rotation is a NAK. | **Pending Rotation** (new material loaded, not active) | Rotate it, in two steps, **before** the pass |
| **Traffic key** | Payload crypto panels (TX Chain and RX Analysis) | AES-256-GCM, symmetric. Encrypts what you send, decrypts what comes down, verifies the auth tag. | Valid, 62 days to expiry | Rotterdam rotates the fleet traffic key on its own schedule. Watch it after the pass. |

Different custody, different schedules. People confuse them constantly. Read both before you touch either.

<Aside type="caution">
Rotation is a handshake, not a swap: **Initiate Key Rotation**, then **Confirm Key Rotation**. The far end acknowledges the new key is loaded before the old one is retired. A one-step swap can leave the two ends on different keys, which is exactly what a **Mismatch** is.
</Aside>

## TT&C Console Reference

| Display | Meaning |
|---------|---------|
| Key badge | Valid / Pending Rotation / Zeroized |
| Initiate Key Rotation | Marks the current key Pending Rotation and stages the new material |
| Confirm Key Rotation | Completes the handshake; the key reads Valid |
| Zeroize (armed-then-fire) | Destroys the key material. **Not part of any rotation.** A zeroized station cannot command anything until re-keyed by Rotterdam, and that does not happen inside a seven-minute pass. |
| NAK: key invalid | Sent under a key that is not Valid |

## End of Briefing

A rotation you complete is hygiene. A rotation the far end completes without you is a mismatch, and the first you hear of it is a decoder that has stopped understanding the spacecraft. Today has one of each.

Finish the command-key rotation before the window. Get the ACK. Then read the traffic key before you touch it.

Good luck.
