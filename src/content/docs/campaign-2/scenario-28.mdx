## Vendor Access - How It Is Supposed to Work

| Step | Requirement |
|------|-------------|
| Ticket | Names the units, the window, the reason |
| Window | Inside the published maintenance window (this week: none) |
| Path | Corporate jump host only; nothing inbound reaches the M&C segment directly |
| Account | `svc-vendor` enabled for the window, disabled after |
| Session | Recorded; an operator on the console while it runs |

The session at 21:12 matches none of these.

<Aside type="caution">
A vendor session with no ticket, outside the window, from an address the baseline has never seen, is either a vendor ignoring the procedure or somebody using the vendor's credentials. From this console those look the same. The answer to both is the same: cut the account, keep the evidence, tell CSIRT.
</Aside>

## What a Session on the M&C Segment Can Reach

Everything on the monitor-and-control path: the ACU (pointing, tracking, limits), the RF front end controller (LNB LO, BUC), the modems, the GPSDO settings, and the workstation it came in through. Not the crypto unit, which has its own path and its own keys. Not the RF itself.

A burst of ACU parameter reads from a session is what mapping the controller looks like.

## Do Not Pull the Site Uplink

The edge router also carries Rotterdam, the monitoring feed, Group Security's path in, and the coordination for the 23:50 pass. The account is the switch that removes exactly the thing that should not be there.
